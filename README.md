# ordinal_regression_STorder

Reproducibility materials for
**"A General Class of Ordinal Regression Models: A Comprehensive Modeling Framework for Different Types of Data Structures"**.

This repository contains the code and data used to reproduce the figures,
simulation studies, and empirical analyses reported in the manuscript and its
Supplementary Material.

## Repository structure

- `code/` contains the R, R Markdown, and Python files used for the analyses.
  See `code/code_sources.md` for a description of every code file.
- `data/` contains the data files supplied with the repository and their
  documentation. See `data/data_sources.md` for the data sources, variables,
  coding, and preprocessing details.
- `results/` is used for CSV files generated by the white-wine analyses. The
  directory may be empty before these analyses are run.

All commands and scripts should be run with the repository root as the working
directory.

## Software requirements

The R analyses require R and the packages used by the individual scripts,
including `CUB`, `VGAM`, `aplore3`, `catdata`, `dplyr`, `ggplot2`,
`gridExtra`, `latex2exp`, `ordDisp`, `ordinal`, `patchwork`, `tidyr`,
`tidyverse`, and `zipfR`.

The white-wine analyses require Python 3 with the following packages:

- `numpy`
- `pandas`
- `torch`
- `scikit-learn`

They also require R, `Rscript`, and the R package `ordinal` because the POM is
fitted in R and evaluated using the same cross-validation splits as the neural
models.

## Reproducing the manuscript results

The files below are independent unless otherwise noted. R Markdown files may
be run chunk by chunk or rendered in full. Numerical summaries are printed in
the R console, and figures are displayed in the R plotting window.

### Main-manuscript figures

- `code/Figure1_converted_Sf.R` reproduces Figure 1.
- `code/Figure2_baseline_Sfs.R` reproduces Figure 2.
- `code/Figure3_transformation_effects.R` reproduces Figure 3.
- `code/Figure4_simulation_study_GCLM.Rmd` reproduces Figure 4 and reports the
  AIC and BIC selection frequencies and the median deviance and MSE from the
  GCLM simulation study.
- `code/Figure5_different_dispersion.R` reproduces Figure 5.
- `code/Figure6_crossing_transformation.R` reproduces Figure 6.

### Supplementary simulation study

- `code/FigureS1_simulation_study_GPPOM.Rmd` reproduces Supplementary Figure
  S1 and reports the AIC and BIC selection frequencies and the median deviance
  and MSE from the GPPOM simulation study.

### Main-manuscript empirical analyses

- `code/Table5_APS.Rmd` reproduces Table 5 for the APS data. It reports the
  full-data estimation results and the out-of-sample LogS and RPS values.
- `code/Table6_retinopathy.Rmd` reproduces Table 6 for the retinopathy data. It
  reports the full-data estimation results and the out-of-sample LogS and RPS
  values.

These R Markdown files source `code/common_functions.R`, which contains the
shared functions for fitting, selecting, and evaluating the proposed ordinal
regression models.

### Supplementary white-wine analyses

Supplementary Tables S2 and S3 use the same repeated stratified
cross-validation assignments supplied in
`data/white_repeated_stratified_5x5.csv`. Continuous covariates are
standardized within each cross-validation split using the corresponding
training data. The reported RPS is the ordinary unnormalized RPS.

Run the seven-category analysis for Supplementary Table S2 from the repository
root:

```bash
python code/TableS2_white_wine.py
```

Run the five-category analysis for Supplementary Table S3:

```bash
python code/TableS3_white_wine.py
```

Each command fits the CMNN GCLM, cumulative softmax GCLM, CI model, SI-CS
model, and POM. The completed table is printed to the console and saved as
`results/TableS2.csv` or `results/TableS3.csv`, respectively.

The neural analyses are computationally intensive. Progress is saved after
each completed fold in a temporary file under `results/`, allowing an
interrupted run to resume when the same command is executed again. The
temporary progress file is removed automatically after the table has been
completed successfully.

`code/white_wine_common.py` contains the shared Python implementation and is
imported automatically. `code/white_wine_POM.R` is called automatically through
`Rscript`. These two supporting files should not normally be run directly.

## Output files

The R analyses display their requested tables and figures directly in R. They
do not require precomputed files in `results/`. The following two CSV files are
created only after the corresponding white-wine analyses finish:

- `results/TableS2.csv`
- `results/TableS3.csv`

Therefore, an initially empty `results/` directory is expected and does not
indicate missing input data.

## Data documentation

The white-wine analysis uses the following repository files:

- `data/wine_white_processed.csv`
- `data/white_repeated_stratified_5x5.csv`

The APS and retinopathy data are loaded from their cited R packages by the
corresponding R Markdown files. Complete source and variable information is
provided in `data/data_sources.md`.
